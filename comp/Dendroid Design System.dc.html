Dendroid

Design System — v0.1

A markdown graph editor. The system is built from three materials: hairlines, monospace, and a 16 px pixel grid. Nothing is rounded, nothing is shadowed, and the interface removes itself when you are writing.

02

Iconography

Every icon is a set of 1×N rectangles on a 16×16 grid, exported as SVG with shape-rendering: crispEdges. Diagonals are stepped single pixels — never smoothed. Curves are octagonal approximations. Icons inherit currentColor and have no active/filled variant; state is carried by color alone.

03

Color

Four themes, one token structure: two aesthetics × light and dark. Grayscale carries all structure; the accent is reserved for exactly three things — the @-link, the current tree root, and text selection. Danger is destructive confirmation only. Each aesthetic owns its accent hue: Terminal is a cold green at high chroma, Parchment a warm amber at the same lightness, so the two never read as the same product with a filter over it.

07

Motion

Two named motions and nothing else. Everything uses cubic-bezier(0.2, 0, 0, 1) in, cubic-bezier(0.4, 0, 1, 1) out. Exits are always faster than entrances.

Deblur — modals
backdrop: blur 0 → 14 px, opacity 0 → 1 · 200 ms content: blur 10 px → 0, opacity 0 → 1 · 240 ms, 40 ms delay out: reverse, 130 ms, no delay
Recede — Zen mode
chrome opacity 1 → 0 · 600 ms, after 1200 ms idle in editor return: opacity → 1 · 120 ms on pointer move or ⌘-key never animates layout — opacity only, so nothing reflows
08

Markdown specimen

Notes are one graph

A heading is a node. Its children are the headings beneath it, so structure emerges from writing instead of filing.

Linking

Type @ to reach any heading, like @Sync providers. Completions are ordered by graph distance, not alphabet.

Structure should be a consequence of thinking, not a prerequisite for it.
  • Child headings are implicit links to their parent
  • Any node can become the editor root
$ dendroid sync --provider file \
    --path ~/notes
